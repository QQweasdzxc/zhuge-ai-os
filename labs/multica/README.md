# Multica Native Lab

Purpose: run a near-native Multica self-host inside the Zhuge AI OS Lab boundary so the PM can evaluate human/agent collaboration before any Zhuge Board 2.0 adoption work.

## Upstream freeze

- Repository: https://github.com/multica-ai/multica
- Commit: `8db6cfe19ae6fd5c35ec71bd8fea42a3ef3861ec`
- License and Multica branding remain intact.

## Zhuge-owned boundaries

- Database: Supabase PostgreSQL, isolated from Zhuge canonical tables.
- Canonical row UUIDs: generated by the Zhuge Lab UUID authority override.
- Runtime: Zhuge-owned machines / cloud runtimes.
- Coding providers: Zhuge-owned Codex / Claude credentials.
- Repository under test: Zhuge-controlled Lab worktree/repository.
- Telemetry: `DO_NOT_TRACK=true`.
- Production credentials and canonical main writes are forbidden in Lab.

## Native behavior intentionally preserved

Board / Issues, Agents, Runs, Runtime coordination, comments, mentions, squads, skills, blockers, retry behavior and Autopilot remain Multica-native for the first experience phase.

## Deployment

Render builds use:
- `labs/multica/Dockerfile.backend`
- `labs/multica/Dockerfile.web`

The backend intentionally clones the frozen upstream commit at build time and overlays only the Zhuge Lab identity boundary. This keeps the upstream product experience intact while making the execution boundary explicit and reproducible.
