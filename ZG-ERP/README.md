# ZG-ERP 庫存 · 設備管理（諸葛模組）

一個應用程式一個資料夾：本資料夾是 ZG-ERP 的全部程式碼，入口在諸葛，程式不散放到其他應用資料夾。

## 狀態：測試資料版（batch 1）

- 目前資料是**虛構測試資料**，只存在使用者的瀏覽器（localStorage），重新整理會保留、清除瀏覽資料會消失。
- **沒有**連接、讀取或寫入任何 Google 試算表或資料庫。
- 相機連續掃描尚未實作（下一批）；目前以手動輸入登記編號或測試按鈕模擬。
- 定位使用瀏覽器實際定位（需使用者授權），只用來找最近據點；失敗時可手動選擇。

## 架構方向（使用者 2026-11-04 指定）

Google 試算表是唯一正式資料來源：設備資料、歸屬專案、位置表、位置圖標記對照、盤點紀錄都在試算表，不另建第二套業務資料。
讀寫比照 `app/Board/procurement/vendor-sheet-service.js` + `supabase/functions/gas-vendor-bridge` 模式（前端 → Supabase Edge Function（Google 服務帳號）→ Sheets API）。
實際表格與欄位待使用者提供後，新增對應的 ERP bridge function 與欄位對照，再切換 `erp-data.js` 的 `DATA_BACKEND`；UI 不需要改寫。

## 檔案

- `index.html` — 入口頁
- `erp-app.js` — 全部畫面與互動（電腦管理端 + 手機掃描端 + 位置圖）
- `erp-data.js` — 資料層（MockStore；SheetsStore 預留）
- `erp.css` — 樣式（沿用設計稿視覺）
- `version.json` — 版本資訊

## 功能（batch 1）

電腦端：總覽儀表板（即時統計、依狀態/歸屬專案篩選、專案反查設備）、設備資料（逐筆編輯保管人/區域/狀態/歸屬專案/S/N/三個日期）、位置表（區域維護）、位置圖（示意平面圖 + 本機圖檔預覽與手動標記，點位置帶出設備）、盤點差異（逐筆決定：維持登記/以現場為準/稍後/標記補登）。
手機端：起點定位（瀏覽器實際定位）→ 連續掃描（手動輸入/測試按鈕）→ 結果（應有/已掃位置表、待決定項目）。

## 不在 batch 1

真實相機掃描、跨裝置同步、寫回試算表、位置圖正式上傳（需私有儲存位置，圖檔不放公開 repo）、權限管理。

## Batch 2（2026-11-04）
- 相機連續掃描：手機模式可開啟相機，優先以 BarcodeDetector 連續辨識 QR／條碼，不支援的瀏覽器（如 iPhone Safari）改用內建 jsQR（Apache-2.0，vendor/jsQR.js）辨識 QR 碼；掃到自動記一筆（同一張 3 秒內不重複計）。不支援相機/辨識或權限被拒時，顯示原因並退回手動輸入；相機 8 秒無回應也會提示。離開掃描畫面自動關閉相機。
- 定位處理：權限拒絕／收不到訊號／逾時各有明確說明；開始盤點時會抓一次起點定位：瀏覽器尚未決定時會跳出一次授權請求，明確拒絕則不問並維持手動據點；起點定位顯示精度（±m）。
- 試算表轉接器設計版 `erp-sheets-adapter.js`：讀取路徑已實作（bridge → 欄位對照 → 與 MockStore 同形），寫入路徑在實際表格確認前一律拒絕；契約測試 `tests/zg-erp-sheets-contract.test.js`（不觸網、不寫表）。
- 入口：經典報表頁（status-classic）新增「庫存・設備管理（ZG-ERP 測試版）」連結。

## UI/UX 改版（2026-11-04，0.2.0-mock.4）
- 儀表板：新增「需要處理」行動區（待修／維修中、保固已到期、未決定的盤點差異，可直接點「處理」進編輯）；各據點盤點進度改為卡片（最沒進度排前面，可直接看設備或去盤點）；各專案使用概況改為表格（台數、使用中、待修/維修、分布據點，點列反查明細）。
- 操作旅程：明細列的「處理」會跳到設備資料並直接打開該筆編輯；「← 回儀表板／位置圖」返回且篩選條件保留。手機儀表板共用同一套內容。
- 手機盤點：開始前可先設定「這次主要盤哪個專案」（預設全部）；掃描中顯示本次範圍的應盤／已掃／未掃進度與未掃清單；掃到範圍外（其他專案／其他據點／查無編號）照樣記錄不隱藏；掃到其他專案的設備會提示歸屬不符，只記錄、不自動改歸屬。結果頁的位置表在設定專案時只算範圍內設備並註明。
