## 1. 總體願景：70/30 視覺比例

依 PM 裁定，保留既有 Habblaud，局部優化為微斜角、開放剖面式 AI 辦公園區：

- **主辦公樓約佔視覺 70%**：顯示核心辦公空間、會議室、獎牌牆、休憩設施；這是構圖目標，不是固定像素或新增一個等角引擎。
- **戶外園區約佔視覺 30%**：保留原有道路、草地、植栽與合理行走空間，為家人、黑灰貓和少數附屬設施保留活動場域。
- **現有能力優先**：原生畫面、路由、互動、HUD、作品連結均保留。
- **本輪不做**：護城河或大水景（`FUTURE_OPTION`）。

## 2. 分區盤點：保留與建議微調

### 2.1 保留（KEEP）

1. Habblaud 原生場景、既有房間／地板／入口及可互動機制。實際格位須由 Co 從 native world 讀取，不能單憑構想認定現況。
2. TaskFlow、WorkLog、Investment、Lab、經典報表等原有作品／報表入口，及 HUD 操作。
3. 原本的戶外草地、樹木、道路與空間層次；保持「辦公園區」而非改建為另一款遊戲。

### 3.1 交付 Co #72 的避障需求

1. 人物不可穿越牆面、會議室隔屏、家具、桌子、吧台。
2. 進出會議室須通過合法門洞；不能直接橫切玻璃。
3. 閒晃時以合法可達站立點為目標；若路徑無法到達，不得直接瞬移。
4. **不要以本文件概念格位代替原生尋路資料。** Co 需提供座標、尺寸、door topology、障礙物格式的回讀證據，再由 Gem 調整設計。

## 4. 桌機／手機視角

- 桌機建議驗證 1920×1080 與 1440×900。構圖以主樓為視覺重心、戶外為生活感陪襯；HUD／側欄不能遮擋主要入口及人物點擊。
- 手機先以現有 native 相機與觸控行為為準，預設聚焦核心辦公區；手勢拖曳、跟隨、彈性偏移若原生尚未支援，需 Co 列成待驗證或另行評估，不能稱「已具備」。
- 可點擊元件以至少 44 CSS px 觸控目標作設計建議，驗收以實際 DOM／Canvas 命中框與真機回歸證據為準。
